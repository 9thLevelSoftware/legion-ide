# Text-editing scope audit (S0-01d)

This audit expands only `COMP-SCOPE-FAMILY-01` (Text editing). The approved
family wording is preserved verbatim below; implementation status is an
inventory signal from baseline `1895fda2da3df49b80a599e48110fca16ecbe1e0`,

`owner_role = luna_worker`, and `acceptance = unassessed`.

## Verbatim governing wording

- Approved family (`docs/superpowers/specs/2026-09-04-product-completion-design.md:51`): “Selection, Unicode, undo/redo, multi-cursor, indentation, wrapping, clipboard, IME, Vim, large-file behavior and predictable input”.
- S1-04 deliverable (`docs/superpowers/plans/2026-09-04-manual-language-completion.md:180`): “Ordinary editing is discoverable and reliable for selections, Unicode/graphemes, undo/redo, multi-cursor, indentation, wrapping, clipboard, IME, Vim, keymap customization, settings profiles and reset.”
- S1-04 focused tests (`docs/superpowers/plans/2026-09-04-manual-language-completion.md:193`): “Add focused failing tests for a Unicode selection/edit/undo chain, multi-cursor insertion, an IME commit after focus change, conflicting keymap binding rejection, and settings reset after restart.”
- S1-04 Vim constraint (`docs/superpowers/plans/2026-09-04-manual-language-completion.md:194`): “Implement only missing translation, focus and persistence links; keep `VimState` pure and route product Vim through `AppComposition::dispatch_vim_key`.”
- Existing exact multi-cursor acceptance (`plans/kanban/legion-ga-backlog.toml:P1.F3.T2 acceptance[2]`): “A second cursor can be created, typed at, and cleared; every cursor is painted.”
- Existing exact Vim acceptance (`plans/kanban/legion-ga-backlog.toml:P1.F3.T5 acceptance[1]`): “A key typed in the code canvas reaches the Vim parser and moves the real cursor or edits the real buffer; normal-mode keys are not also inserted as text.”
- Existing exact large-file acceptance (`plans/kanban/legion-ga-backlog.toml:P1.F4.T2 acceptance[1]`): “100MB file opens within budget, scrolls, and does not block typing.”
