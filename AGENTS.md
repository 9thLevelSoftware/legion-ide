# AGENTS.md

This file provides guidance to agents when working with code in this repository.

- Phase gates (21 standing gates): `cargo run -p xtask -- check-deps`; `cargo run -p xtask -- docs-hygiene`; `cargo run -p xtask -- claim-audit`; `cargo run -p xtask -- no-egui-textedit`; `cargo run -p xtask -- verify-kanban-backlog`; `cargo run -p xtask -- verify-readiness-consistency`; `cargo run -p xtask -- release-pipeline --dry-run`; `cargo run -p xtask -- verify-release-pipeline`; `cargo fmt --all --check`; `cargo check --workspace --all-targets`; `cargo test --workspace --all-targets`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo deny check`; `cargo run -p xtask -- rust-analyzer-smoke`; `cargo run -p xtask -- golden-path-1`; `cargo run -p xtask -- golden-path-2`; `cargo run -p xtask -- golden-path-3`; `cargo run -p xtask -- golden-path-4`; `cargo run -p xtask -- perf-harness`; `cargo run -p xtask -- verify-perf-harness`; `cargo run -p xtask -- update-drill`; local full phase-gate scripts run `cargo deny check` when cargo-deny is installed. GitHub Actions workflows: `.github/workflows/legion-gates.yml` runs the standing gate set (xtask gates, fmt/check/test/clippy, cargo-deny, perf-harness + verify-perf-harness on the 3-OS PR matrix with skeleton budgets report-only and product-workload coverage enforced, rust-analyzer-smoke when rustup provision succeeds) on ubuntu/windows/macos for every push to main and every PR; `.github/workflows/legion-bench.yml` runs recorded-mode legion-bench on **every push to main and every PR**; recorded mode **executes real fixture tasks** (copies the fixture repo, drives the delegated-task loop, applies proposals through the real proposal pipeline, runs each task's verification command) with the model's responses replayed from committed cassettes under `evals/legion-bench/recorded/`, so it needs no model, no endpoint and no credential (`scoring_mode=recorded_replay_execution`); `verify-legion-bench` compares the measured per-task result against `evals/legion-bench/recorded/baseline.toml` and fails on any difference. `legion-bench --mode record` cuts new cassettes from a live endpoint and `--mode live-local` runs live without recording (`LEGION_BENCH_MODEL`/`LEGION_BENCH_ENDPOINT`; corpus at `evals/legion-bench/tasks/`, holdout tasks skipped unless `--include-holdout`). Live mode is confined to `.github/workflows/legion-bench-live.yml`, which has no push/PR trigger and is `continue-on-error`, so no CI gate can require a provider; `.github/workflows/legion-smoke.yml` runs the GP-1/2/3/4 golden-path smokes and the update-drill (headless delegate mode flows: fixture edit/LSP/git for GP-1; scope/sandbox/kill-switch for GP-2; full delegate task loop with scope denial and evidence TOML for GP-3; automate multi-agent workflow evidence for GP-4; deterministic update/rollback with ephemeral key for the update-drill) on dispatch and weekly (Mondays 06:00 UTC) on the 3-OS matrix — it is an INDEPENDENT workflow and failures do NOT block PR merges. Promote smoke to merge-blocking only after the criteria in `docs/OPERATOR_RUNBOOK.md` (four consecutive green 3-OS scheduled runs + owner sign-off). Local gates remain the primary verification source until the hosted gate history is proven stable; the evals/training pytest suite is local-only for now.
- WS17.T1 release pipeline: `xtask release-pipeline --dry-run --channel {stable,preview}` writes per-target TOML descriptors plus a `version_stamp.toml` (schema_version, package_version, channel, rollout_policy, dist_tool, git_sha, built_at_utc) to `target/release-pipeline/`; `xtask verify-release-pipeline` re-plans from the config and emits `verify_report.toml` with per-descriptor `verifier_status` (currently `dry-run/unchecked` until WS17.T2 ships real signing). `.github/workflows/legion-release.yml` is a manual `workflow_dispatch` unsigned-beta native installer workflow (verify-only or publish); it is not a PR merge gate and does not use production OS signers. No private signing keys, certs, tokens, or notarization credentials may be committed; descriptors may only carry `dry-run/no-production-signer` until WS17.T2 lands.
- WS18.T1 performance harness: `xtask perf-harness` runs the M0 perf-harness skeleton (a deterministic in-process input-to-paint microbenchmark) and writes `target/perf-harness/perf_report.toml` (schema_version, package_name, measured_at_utc, git_sha, summary {total, passed, failed, skipped}, per-skeleton measurements with total/p50/p95 in microseconds + budget + status); `xtask verify-perf-harness` re-reads the report and re-applies the strict gate. Hosted `legion-gates.yml` runs both commands on the 3-OS PR matrix; skeleton microbenchmark budgets stay report-only, product-workload coverage is enforced, and those steps currently set `LEGION_PERF_FAIL_ON_BUDGET_MS=0`. A `LEGION_PERF_FAIL_ON_BUDGET_MS=<ms>` environment override tightens the per-skeleton budget; setting it to `0` disables the budget fail for a local run. The full per-OS reference workloads (Legion repo, 100K-file fixture, 100MB file, scroll-jank, startup, memory ceiling) and the cross-runner dashboard remain follow-on work for renderer-backed 3-OS paint evidence.
- Single test examples: `cargo test -p legion-app --test workspace_vfs_integration workspace_vfs_integration_external_overwrite_between_open_and_save_yields_conflict`; list editor perf tests with `cargo test -p legion-editor --test performance_suite -- --list`.
- `xtask check-deps` parses `plans/dependency-policy.md` sections 1/2 and also hardcodes required deps plus forbidden `legion-editor -> legion-project`; update policy/protocol symbols and `xtask` together.
- Current UI shell is projection-only: `legion-ui` emits `CommandDispatchIntent` and accepts snapshots; do not put editor session/text ownership back into UI.
- Saves are proposal-mediated: `AppComposition::save_active_buffer` -> `SaveWorkflowService` -> `WorkspaceActor::save_file_with_proposal`; stale/conflict/denial returns `Ok(AppSaveOutcome::Rejected(_))` while preserving dirty editor text.
- Workspace saves require expected fingerprint, file content version, workspace generation, buffer version, snapshot id, and non-zero correlation/causality; non-atomic write fallback is intentionally disabled/fail-closed.
- `legion-text` snapshots materialize a full cache and line index with a 5 MiB budget; `TextBuffer::from_reader` / `from_file` and `EditorEngine::open_buffer_streaming` build the rope incrementally via `Rope::from_reader`, bypassing the `String` intermediate for large files. The app layer selects the streaming path automatically when text exceeds the large-file threshold.
- Observability sinks default to metadata-only redaction and reject zero `CorrelationId`, nil `CausalityId`, or zero `EventSequence`; tests assert event ordering for save/proposal flows.
- Active crates: `legion-index`, `legion-agent`, `legion-tracker`, `legion-memory`, `legion-ai`, and `legion-ai-providers` have real behavior and contract tests and are no longer inert placeholders. Still-deferred surfaces within the AI/provider stack and elsewhere remain protected. Future surfaces in any crate require an ADR/phase gate, dependency-policy entry, and contract tests before activation.
- Vim modal editing: `legion-ui::vim::VimState` is a pure keystroke parser. The desktop + session path is live and opt-in (`AppComposition::dispatch_vim_key`, `VimSession`, `DesktopAction::VimKey`). `AppComposition::dispatch_ui_intent` intercepts Vim intents via `dispatch_vim_intent` before the pure router. `CommandDispatcher` still maps `CommandDispatchIntent::Vim*` to `Noop` as an exhaustiveness stub; that Noop is not the product path.
- Surface expansion freeze (ADR-0046) is **retired** (2026-08-21). New surfaces are scheduled through the roadmap and evidenced through the readiness ledger like any other work. PR-VSC-002, PR-ENT-001 and PR-ENT-002 are still deferred — on their own lack of evidence now, not by the freeze — and `xtask deferred-surfaces` still fails a row that claims more than it can show.
- Some architecture review docs describe earlier gaps; verify against current code/tests before repeating claims about UI owning editor state or saves bypassing proposals.
- `cargo run -p legion-app -- <path>` opens the current directory as a trusted workspace and supports only `:w`/`:q`; it is a CLI shell proof, not the real renderer.
