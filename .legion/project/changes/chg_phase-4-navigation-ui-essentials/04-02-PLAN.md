<objective>

Output: Modified legion-app, legion-desktop view and bridge.
</objective>

- `AppComposition` in `crates/legion-app/src/lib.rs` handles `CommandDispatchIntent` variants in a large `match` block

## What's Already Built — Keyboard Handling
- Hardcoded checks: `ui.input(|i| i.key_pressed(egui::Key::F12))` for go-to-definition (line ~2349)
- `ui.input(|i| i.modifiers.ctrl)` for Ctrl detection
- These inline checks will remain for context-dependent keys; the keymap handles the rest

## Constraints
- The find bar should render ABOVE the code canvas, anchored to the top-right of the editor area (standard VS Code position)
- Use `egui::Area` for the find bar (consistent with existing popup pattern)
- Match highlights paint on EVERY visible line, not just the current match — use yellow/gold for all matches, orange for the current match
- Keybinding dispatch runs BEFORE existing hardcoded key checks so it can be overridden
- Do NOT add new dependencies

Initialize it with `BufferSearchState::default()` in the constructor (`AppComposition::new()`).

Find the `CommandDispatchIntent` match block (the large match that handles all intents). Add handlers for each find intent:

- `ToggleFindBar`: toggle `self.buffer_search_state.find_bar_visible`. If becoming visible, no-op on query. If becoming invisible, clear matches.
- `CloseFindBar`: set `find_bar_visible = false`, clear matches.
- `SetFindQuery { query }`: set `self.buffer_search_state.query = query`. If query is non-empty and there's an active buffer, get buffer text via `self.editor.text(active_buffer_id)` and call `self.buffer_search_state.find_matches(text)`.
- `FindNext`: call `self.buffer_search_state.next_match()`. If there's a current match, set the editor cursor to that position.
- `FindPrevious`: call `self.buffer_search_state.prev_match()`. If there's a current match, set the editor cursor.
- `ToggleFindReplace`: toggle `self.buffer_search_state.replace_visible`. Also ensure `find_bar_visible = true`.
- `SetFindReplaceText { text }`: set `self.buffer_search_state.replace_text = text`.
- `ReplaceOne`: if there's a current match, use `self.editor.apply_edit()` to replace the match range with `replace_text`. Then re-run `find_matches` and advance to next.
- `ReplaceAll`: iterate all matches in reverse order (to preserve byte offsets), apply replacements via `apply_edit`. Then re-run `find_matches`.
- `SetFindCaseSensitive { enabled }`: set flag, re-run `find_matches` if query non-empty.
- `SetFindWholeWord { enabled }`: set flag, re-run `find_matches` if query non-empty.
- `SetFindRegex { enabled }`: set flag, re-run `find_matches` if query non-empty.

For cursor positioning on FindNext/FindPrevious, the current match gives `(start_line, start_char, _, _)`. Use an existing `SetCursor` intent or direct cursor API to move the viewport to the match position.

Implementation:
- Only proceed if `find_bar.visible` and `!find_bar.matches.is_empty()`
- Filter matches where `match.start.line <= line_zero && match.end.line >= line_zero` (where `line_zero = line.number - 1`, since TextCoordinate is 0-based and line.number is 1-based)
- For each matching range on this line:
  - Compute `start_x = response.rect.left() + (start_char as f32 * char_width)`
  - Compute `end_x = response.rect.left() + (end_char as f32 * char_width)`
  - Determine color: if this match index == `find_bar.current_match_index`, use orange `Color32::from_rgba_premultiplied(255, 152, 0, 120)`, otherwise use yellow `Color32::from_rgba_premultiplied(255, 235, 59, 80)`
  - Paint a filled rectangle: `ui.painter().rect_filled(egui::Rect::from_min_max(pos2(start_x, response.rect.top()), pos2(end_x, response.rect.bottom())), 0.0, color);`

To know which match index each match is, iterate `find_bar.matches` with `enumerate()` and filter by line, passing the index for color selection.
