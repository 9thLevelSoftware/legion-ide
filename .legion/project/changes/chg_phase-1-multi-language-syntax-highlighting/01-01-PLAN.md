## Current Dispatch Architecture (MUST be replaced, not extended)
The current code uses a boolean gate pattern in 4+ places:
1. `tree_sitter_language_is_bundled_rust(lang_id)` (line 2651) — returns true only for "rust"/"rs"
2. `tree_sitter_supports_path(path)` (line 2656) — checks `.rs` extension only
3. `highlight_captures_from_text(lang_id, src)` (line 2459) — guards with `!tree_sitter_language_is_bundled_rust`, returns empty Vec
4. `code_chunk_descriptors_from_text(lang_id, src)` (line 2507) — same guard, returns empty Vec
5. `TreeSitterParser::parse()` (line 2526) — same guard, falls back to LexicalFallbackParser with diagnostic

All 5 sites must be updated to dispatch through the new per-language table.

## Plugin Grammar Registry Interaction
`PLUGIN_TREE_SITTER_GRAMMAR_REGISTRY` (line 2673) exists for runtime-loaded WASM grammars. `tree_sitter_supports_language()` (line 2644) checks `is_bundled_rust || plugin_registered`. The new architecture must:
- Replace `tree_sitter_language_is_bundled_rust()` with `tree_sitter_language_is_bundled(lang_id)` that checks all built-in languages
- Keep the plugin registry path intact — plugins register separately and fall back to lexical parsing (no loaded-grammar workers yet)
- `tree_sitter_supports_language()` naturally covers both built-in and plugin-registered

## Capture Name Normalization (already works)
`tree_sitter_capture_kind()` (line 2627) splits on `.` and takes the base segment:
- `keyword.control` → Keyword, `type.builtin` → Type, etc.
- Fallback: anything unmapped → Ident
This handles cross-grammar capture name differences without any changes.

## Task 2: Replace boolean dispatch with per-language table

This is an **architectural replacement**, not a simple extension. The boolean `tree_sitter_language_is_bundled_rust()` gate must become a per-language dispatch table.

### In `crates/legion-index/src/lib.rs`:

**a) Create `language_for_path()` function:**
```rust
pub fn language_for_path(path: &str) -> Option<LanguageId> {
    let ext = std::path::Path::new(path).extension()?.to_str()?;
    let lang = match ext.to_ascii_lowercase().as_str() {
        "rs" => "rust",
        "py" | "pyi" => "python",
        "ts" => "typescript",
        "tsx" => "tsx",
        "js" | "mjs" | "cjs" => "javascript",
        "jsx" => "jsx",
        "go" => "go",
        "c" | "h" => "c",
        "json" => "json",
        "toml" => "toml",
        "md" | "markdown" => "markdown",
        "sh" | "bash" | "zsh" => "bash",
        _ => return None,
    };
    Some(LanguageId(lang.to_string()))
}
```

**b) Update `tree_sitter_supports_path()` to delegate:**
```rust
pub fn tree_sitter_supports_path(path: &str) -> bool {
    language_for_path(path).is_some()
}
```

**c) Replace `tree_sitter_language_is_bundled_rust()` with `tree_sitter_language_is_bundled()`:**
```rust
fn tree_sitter_language_is_bundled(language_id: &LanguageId) -> bool {
    matches!(language_id.0.as_str(),
        "rust" | "rs" | "python" | "typescript" | "tsx" | "jsx" | "javascript"
        | "go" | "c" | "json" | "toml" | "markdown" | "bash"
    )
}
```
Update `tree_sitter_supports_language()` (line 2644) to use this instead of `tree_sitter_language_is_bundled_rust()`.
**KEEP `tree_sitter_language_is_bundled_rust()` — it is still needed** by `code_chunk_descriptors_from_text()` and `TreeSitterParser::parse()` (see Task 2g).

**d) Create per-language `OnceLock` language + query pairs.**
Follow the exact pattern of `rust_tree_sitter_language()` and `rust_highlight_query()`.
Use the correct export names per the API survey above:

- Python: `tree_sitter_python::LANGUAGE`, `tree_sitter_python::HIGHLIGHTS_QUERY`
- TypeScript: `tree_sitter_typescript::LANGUAGE_TYPESCRIPT`, `tree_sitter_typescript::HIGHLIGHTS_QUERY`
- TSX: `tree_sitter_typescript::LANGUAGE_TSX`, `tree_sitter_typescript::HIGHLIGHTS_QUERY` (same query)
- JavaScript (.js/.mjs/.cjs): reuse TypeScript — `tree_sitter_typescript::LANGUAGE_TYPESCRIPT`, `tree_sitter_typescript::HIGHLIGHTS_QUERY`
- JSX (.jsx): reuse TSX — `tree_sitter_typescript::LANGUAGE_TSX`, `tree_sitter_typescript::HIGHLIGHTS_QUERY` (JSX syntax requires the TSX grammar)
- Go: `tree_sitter_go::LANGUAGE`, `tree_sitter_go::HIGHLIGHTS_QUERY`
- C: `tree_sitter_c::LANGUAGE`, `tree_sitter_c::HIGHLIGHT_QUERY` (**singular**)
- JSON: `tree_sitter_json::LANGUAGE`, `tree_sitter_json::HIGHLIGHTS_QUERY`
- TOML: `tree_sitter_toml_ng::LANGUAGE`, `tree_sitter_toml_ng::HIGHLIGHTS_QUERY`
- Bash: `tree_sitter_bash::LANGUAGE`, `tree_sitter_bash::HIGHLIGHT_QUERY` (**singular**)
- Markdown: `tree_sitter_md::LANGUAGE` (block only), `tree_sitter_md::HIGHLIGHT_QUERY_BLOCK` (**singular**)

**e) Create dispatch functions:**
```rust

```

**f) Generalize `tree_sitter_highlight_captures()` → `tree_sitter_highlight_captures_for(lang_id, source)`:**
Replace the hardcoded Rust call with dispatch through the new table.

**g) Update boolean-gated call sites (DIFFERENT guards for different sites):**

1. `highlight_captures_from_text()` (line 2459): replace `!tree_sitter_language_is_bundled_rust` guard with `!tree_sitter_language_is_bundled` guard, dispatch to `tree_sitter_highlight_captures_for(language_id, source)`. This is the ONLY site that gets the broadened guard + multi-language dispatch.

2. `code_chunk_descriptors_from_text()` (line 2507): **KEEP the `tree_sitter_language_is_bundled_rust()` guard unchanged.** The code after this guard calls `tree_sitter_code_chunk_descriptors(source)` which uses `parse_tree_sitter_rust()` internally. Widening this guard would cause Python/Go/etc. files to be parsed with the Rust grammar, producing corrupt chunk data. Non-Rust languages correctly return empty Vec here.

3. `TreeSitterParser::parse()` (line 2526): **KEEP the `tree_sitter_language_is_bundled_rust()` guard unchanged.** The body calls `parse_tree_sitter_rust()` and `rust_tree_sitter_symbol_records()` — all Rust-specific. Widening would route non-Rust files into Rust structural parsing and suppress the correct `LexicalFallbackParser` + diagnostic fallback. Non-Rust bundled languages still get lexical fallback here (same as today's behavior for plugin-registered languages).

4. `tree_sitter_supports_language()` (line 2644): use `tree_sitter_language_is_bundled()` instead of `tree_sitter_language_is_bundled_rust()`. This correctly reports all built-in languages as supported.

**KEY PRINCIPLE**: Only *highlighting* is multi-language in this plan. Structural parsing (outlines, code chunks, symbol extraction) remains Rust-only. This is safe because the rendering pipeline only consumes highlight captures, not structural parse data.
