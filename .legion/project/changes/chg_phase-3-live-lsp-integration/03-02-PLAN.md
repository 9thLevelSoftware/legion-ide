# Plan 03-02 — Completion Popup + Hover Tooltip + Go-to-Definition

<objective>
Build the editor UI for LSP completions (dropdown popup with insert-on-accept), hover information tooltips, go-to-definition navigation, and inlay hints rendering.

Agent: engineering-senior-developer
</objective>

<context>
## Depends On
- Plan 03-01: Diagnostic rendering is in place, establishing the pattern for LSP-driven editor decorations

## What's Already Built — Protocol Types
All projection types are in `crates/legion-protocol/src/lib.rs`:

- `LanguageCompletionProjection` (line 16352): `completion_id: String`, `label: String`, `detail_label: Option<String>`, `kind_label: String`, `score_basis_points: u16`, `degraded: bool`, plus `insert_text: Option<String>` for insertion
- `LanguageHoverProjection` (line 16331): `hover_id: String`, `file_id: Option<FileId>`, `range: Option<ProtocolTextRange>`, `label: String`, `summary: String`
- `LanguageLocationProjection` (line 16376): `location_id: String`, `file_id: Option<FileId>`, `path: Option<CanonicalPath>`, `range: Option<ProtocolTextRange>`, `label: String`
- `LanguageInlayHintProjection` (line 16287): `hint_id: String`, `label: String`, `kind_label: String`, `position: TextCoordinate`, `range: Option<ProtocolTextRange>`, `padding_left: bool`, `padding_right: bool`
- `TextCoordinate`: `line: u32` (0-based), `character: u32` (0-based)

## What's Already Built — DesktopAction Variants (in bridge.rs)
All needed action variants ALREADY EXIST:
- `DesktopAction::RequestCompletion { position: TextCoordinate }` — triggers LSP completion request
- `DesktopAction::CompletionNext` — move selection down in popup
- `DesktopAction::CompletionPrev` — move selection up in popup
- `DesktopAction::CompletionAccept` — insert selected completion
- `DesktopAction::CompletionDismiss` — close popup
- `DesktopAction::RequestHover { position: TextCoordinate }` — triggers LSP hover request
- `DesktopAction::HoverDismiss` — close hover tooltip
- `DesktopAction::GoToDefinition { position: TextCoordinate }` — triggers definition request
- `DesktopAction::NavigateToDefinition { index: usize }` — navigate to definitions[index]

## What's Already Built — Editor Rendering
- `render_code_lines()` at `view.rs:2038` iterates `model.active_buffer_code_lines` with per-line rendering
- `snapshot.language_tooling_projection` is accessible — has `completions`, `hover`, `definitions`, `inlay_hints` fields
- `code_char_width()` returns monospace character width for coordinate calculations
- `editor_coordinate_for_line_x()` converts pixel x to `TextCoordinate`
- Overlay painting pattern: `paint_current_line_highlight()`, `paint_code_cursor()` use `ui.painter()` on response rects
- Plan 03-01 established the pattern for `paint_diagnostic_underlines()` and `show_diagnostic_tooltip()`

## Constraints
- All rendering reads from existing projection types — no new protocol types
- `code_canvas_painter.rs` stays as a thin delegation trait — add rendering logic in `view.rs`
- Completion popup state tracked via `egui::Memory` using typed temp data (same pattern as drag anchor state in render_code_lines)
- Use `egui::Area` for floating popups (not `egui::Window` — no title bar needed)
</context>

## Task 1: Completion Popup

Read `crates/legion-desktop/src/view.rs` to find `render_code_lines()` and understand the per-line rendering loop and coordinate system.

1. Add a completion popup rendering function in `view.rs`:

```rust
fn render_completion_popup(
    ui: &mut egui::Ui,
    completions: &[LanguageCompletionProjection],
    cursor_screen_pos: egui::Pos2,
    actions: &mut Vec<DesktopAction>,
)
```

Implementation:
- Only render if `completions` is not empty
- Track selected index via `egui::Memory` temp data with a stable ID: `ui.ctx().data_mut(|d| d.get_temp::<usize>(completion_sel_id))`, defaulting to 0
- Use `egui::Area::new(egui::Id::new("lsp_completion_popup")).fixed_pos(pos2(cursor_screen_pos.x, cursor_screen_pos.y + 20.0)).show(ui.ctx(), |ui| { ... })`:
  - Set max height ~200px, max width ~400px with `ui.set_max_width(400.0); ui.set_max_height(200.0);`
  - `egui::ScrollArea::vertical().show(ui, |ui|` for scrollable list
  - Show at most 10 visible items at a time
  - For each completion (enumerate with index):
    - `let selected = index == selected_index;`
    - `ui.horizontal(|ui| { ... })`:
      - Kind badge: `ui.label(theme::code_muted(&completion.kind_label));` (shows "fn", "var", "kw", etc.)
      - Label: `ui.label(theme::code(&completion.label));`
      - Detail (if present): `ui.label(theme::muted(detail));`
    - If `selected`: paint a subtle background highlight on the row

2. Handle keyboard events for completion navigation:
   - In `render_code_lines()`, when completions are non-empty, intercept keyboard events BEFORE the normal editor key handling:
     - Arrow Down → `actions.push(DesktopAction::CompletionNext)` and increment selected index in Memory
     - Arrow Up → `actions.push(DesktopAction::CompletionPrev)` and decrement selected index
     - Enter or Tab → `actions.push(DesktopAction::CompletionAccept)`
     - Escape → `actions.push(DesktopAction::CompletionDismiss)` and clear selected index from Memory

3. Call `render_completion_popup` from `render_code_lines()` after the line rendering loop, using the current cursor's screen position from the most recent cursor paint position.

## Task 2: Hover Information Tooltip

Read `crates/legion-desktop/src/view.rs` to understand the hover pattern from diagnostic tooltips (Plan 03-01).

1. Add hover tooltip rendering in `view.rs`:

```rust
fn render_hover_tooltip(
    ui: &egui::Ui,
    hover: &LanguageHoverProjection,
)
```

Implementation:
- Use `egui::show_tooltip_at_pointer(ui.ctx(), egui::Id::new("lsp_hover_tooltip"), |ui| { ... })`:
  - `ui.set_max_width(400.0);`
  - Show `hover.label` in code font: `ui.label(theme::code(&hover.label));`
  - If `hover.summary` is non-empty, add separator then show summary: `ui.separator(); ui.label(&hover.summary);`

2. Hover request debouncing — in `render_code_lines()`, per-line in the line loop:
   - When `response.hovered()` and no diagnostic tooltip is showing:
     - Get hover position, compute `TextCoordinate` using `editor_coordinate_for_line_x()`
     - Track last hover request position in `egui::Memory` temp data with a stable ID
     - If position changed from last request: push `DesktopAction::RequestHover { position }`
     - Update stored position

3. Show the hover tooltip: after the line rendering loop, if `snapshot.language_tooling_projection.hover.is_some()`, call `render_hover_tooltip`.

4. Dismiss: when the mouse moves to a different word (position changed) or the user starts typing, push `DesktopAction::HoverDismiss`.

**Verify**: `cargo check -p legion-desktop`

## Task 3: Go-to-Definition + Inlay Hints

Read `crates/legion-desktop/src/view.rs` to find the click handling in `render_code_lines()` (around line 2218 where `response.clicked()` is handled).

**Go-to-definition:**
1. In the per-line click handler in `render_code_lines()`:
   - After the existing `response.clicked()` block, add Ctrl+Click detection:
     ```rust
     if response.clicked() && ui.input(|i| i.modifiers.ctrl) {
         actions.push(DesktopAction::GoToDefinition { position: coordinate });
     }
     ```
   - Make sure Ctrl+Click takes priority over the normal `SetCursor` action (check ctrl modifier before pushing SetCursor)

2. In the keyboard handler in `interactive_fields.rs`:
   - Add F12 key detection: when F12 is pressed with editor focused, push `DesktopAction::GoToDefinition { position: current_cursor }`

3. Definition navigation: after the line rendering loop in `render_code_lines()`, if `!snapshot.language_tooling_projection.definitions.is_empty()`:
   - If exactly 1 definition: immediately push `DesktopAction::NavigateToDefinition { index: 0 }`
   - If multiple: show a small `egui::Area` popup listing definitions with `path` and `label`, clicking one pushes `NavigateToDefinition { index }`

4. Ctrl+hover visual feedback: in the per-line rendering, when `ui.input(|i| i.modifiers.ctrl)` and `response.hovered()`:
   - Underline the hovered word using `ui.painter().line_segment()` with a link-style color (`Color32::from_rgb(75, 156, 211)`)

**Inlay hints:**
5. Add inlay hint rendering function in `view.rs`:

```rust
fn paint_inlay_hints(
    ui: &egui::Ui,
    line: &CodeLineProjection,
    response: &egui::Response,
    inlay_hints: &[LanguageInlayHintProjection],
    char_width: f32,
)
```

Implementation:
- Filter hints where `hint.position.line + 1 == line.number` (0-based to 1-based)
- For each matching hint:
  - Compute x position: `response.rect.left() + (hint.position.character as f32 * char_width)`
  - If `hint.padding_left`: add `char_width * 0.5` spacing before
  - Paint hint label as ghost text using `ui.painter().text()`:
    - Position: `pos2(x, response.rect.top())`
    - Font: monospace, same size as code
    - Color: `Color32::from_rgba_premultiplied(150, 150, 150, 128)` (gray at ~50% opacity)
  - Format: prepend `: ` for type hints (kind_label contains "type"), prepend nothing for parameter hints

Call `paint_inlay_hints` inside the per-line loop in `render_code_lines()`, after `paint_diagnostic_underlines`.
