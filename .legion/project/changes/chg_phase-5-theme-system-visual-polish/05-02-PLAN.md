# Plan 05-02: Tab Bar Polish

<objective>
Agent: engineering-senior-developer

Polish the tab bar with per-tab close buttons (×), horizontal scroll overflow handling,
and drag-to-reorder. This transforms the basic tab strip into a production-quality
tab bar matching VS Code conventions.
</objective>

<context>
## Phase Context
Phase 5: Theme System & Visual Polish. Wave 1 (Plan 05-01) consolidated theme colors.
This plan polishes the tab bar rendering.

## Existing Tab Bar Implementation
- `render_tab_strip()` at `view.rs:2217-2288` — renders tabs with active/inactive styling
- Tab rendering uses `egui::Button` with `bg.code` fill (active) or `bg.panel` fill (inactive)
- Fixed height 34.0 with `pane_frame(bg.panel)` wrapper
- Left-click → `DesktopAction::SwitchTab { buffer_id }`
- Right-click → context menu with Close, Close Others, Close All
- No × close button on tabs (close only via context menu)
- No overflow handling
- No reordering

## Existing Bridge/Intent Pattern
- `DesktopAction::CloseTab { buffer_id }` already exists in `bridge.rs`
- `CommandDispatchIntent::CloseTab { buffer_id }` already exists in `ui.rs`
- Tab switch: `DesktopAction::SwitchTab { buffer_id }` → `CommandDispatchIntent::SwitchTab { buffer_id }`
- The bridge is 1:1 passthrough for these actions

## Prior Plan Outputs
- Plan 05-01 SUMMARY.md — theme color consolidation complete, all colors use theme tokens

## egui API Notes
- `egui::ScrollArea::horizontal()` provides scroll container with scrollbar
- `egui::Sense::click_and_drag()` detects drag gestures
- `response.dragged()` and `response.drag_delta()` for drag tracking
- `response.hovered()` for hover state (show × button)
- `ui.interact(rect, id, Sense)` for custom interaction regions
</context>

## Task 1: Add Close Button to Each Tab

### Actions
1. Read `crates/legion-desktop/src/view.rs` — find `render_tab_strip()` (around line 2217)
2. Modify tab rendering to include a × close button:
   - Show × button when tab is hovered OR active
   - Use `tokens().text.muted` color for × glyph, `tokens().text.primary` on hover
   - × button click fires `DesktopAction::CloseTab { buffer_id }` and consumes the click
     (so it doesn't also trigger SwitchTab)
   - × button is a small clickable area (~12px) at the right edge of the tab
   - For dirty (modified) tabs, show the dirty indicator (●) in place of × when not hovered,
     × when hovered
3. Ensure tab left-click still fires `SwitchTab` only when × is not clicked

### Verify
```
cargo check -p legion-desktop
cargo test -p legion-desktop
```

### Done
Each tab shows × on hover/active. Clicking × closes the tab. Dirty tabs show ● → × on hover.

## Task 2: Add Tab Overflow Scrolling

### Actions
1. In `render_tab_strip()`, wrap the tab rendering loop in `egui::ScrollArea::horizontal()`:
   ```rust
   egui::ScrollArea::horizontal()
       .auto_shrink([false, false])
       .show(ui, |ui| {
           ui.horizontal(|ui| {
               // existing tab rendering loop
           });
       });
   ```
2. This automatically enables horizontal scrolling when tabs exceed available width
3. Style the scrollbar to be subtle: `scroll_bar_visibility(egui::scroll_area::ScrollBarVisibility::VisibleWhenNeeded)`
4. Ensure active tab is scrolled into view when switching tabs — egui does this automatically when the active tab's response is created in the visible area, but verify
5. Test with many tabs (open 20+ files) to verify scroll behavior

### Verify
```
cargo check -p legion-desktop
```

### Done
Tab strip scrolls horizontally when tabs exceed available width. Scrollbar appears on hover/overflow.

## Task 3: Add Tab Drag-to-Reorder

### Actions
1. Add `DesktopAction::ReorderTab { buffer_id: BufferId, new_index: usize }` to `bridge.rs`
2. Add `CommandDispatchIntent::ReorderTab { buffer_id: BufferId, new_index: usize }` to `ui.rs`
3. Wire bridge translation: `ReorderTab` → `CommandDispatchIntent::ReorderTab`
4. Add `AppCommandRequest::ReorderTab` and handler in `legion-app/src/lib.rs`:
   - Reorder the `tabs` vec in `DailyEditingProjection` to move `buffer_id` to `new_index`
   - Return `AppCommandOutcome::Noop` (no visible state change beyond tab order)
5. In `render_tab_strip()`, add drag-to-reorder interaction:
   - Use `egui::Sense::click_and_drag()` for each tab button
   - Track drag state: `dragging_tab: Option<BufferId>` in a local `thread_local!` or passed via model
   - On drag start: record source tab buffer_id and original position
   - During drag: show insertion indicator (vertical line) between tabs at the cursor position
   - On drop: fire `DesktopAction::ReorderTab { buffer_id, new_index }` with the drop position
6. Add bridge test assertion for `ReorderTab` in `intent_bridge.rs`

### Verify
```
cargo check -p legion-desktop
cargo check -p legion-app
cargo test -p legion-desktop --test intent_bridge
```

### Done
Tabs can be dragged to reorder. Bridge test covers ReorderTab action routing.
